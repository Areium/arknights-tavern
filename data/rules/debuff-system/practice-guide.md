# 失败后Roll点机制 - 实践指南

## 快速参考

### 决策流程

```
玩家行为失败（total < DC）
  ↓
判断是否是"高风险失败"？
  ├─ 否 → 直接输出失败叙事，结束
  └─ 是 → 继续
       ↓
      输出"初始失败"叙事
       ↓
      掷"失败后roll"
       ↓
      根据结果输出"后果升级"或"避险"叙事
```

### 快速判定表

| 你在想... | 触发失败后roll? |
|----------|:---------------:|
| 潜入失败被发现 | ✓ 是 |
| 试图欺骗权威被识破 | ✓ 是 |
| 与敌人对抗失败 | ✓ 是 |
| 失手掉了东西 | ✗ 否 |
| 没想到好的借口 | ✗ 否 |
| 大失败(roll=1) | ✓ **一定是** |

## 完整案例模板

### 案例1：潜入房间失败

```
【原始情景】
玩家说："我试图不被发现地进入会议室。"
DC: 14（需要躲避摄像头）
roll: 9（含属性修正）
结果：失败 (9 < 14)

【LLM第一步：初始失败叙事】
"你贴着墙边缓缓靠近摄像头的死角。还差两米——
突然，走廊那边传来脚步声。一个保安正从另一端走来。
你按住呼吸，紧贴墙壁。他经过了。你松了口气。

但就在这时，一个摄像头的转向声——'嗞'——变得清晰。
一个红点在你的胸口闪过。

监控室里，肯定有人注意到了这个异常。"

【LJM第二步：判断是否需要失败后roll】
- 失败幅度：9 vs 14 = -5 ✓ 触发条件1
- 风险等级：被发现是高风险 ✓ 触发条件2
→ 决定进行失败后roll点

【LLM第三步：计算失败后roll】
角色属性：敏捷 +1
情境修正：被发现的高风险 -2
负面惩罚值：严重失败 -3
骰子结果：d20 = 8

失败后roll = 8 + 1 - 2 - 3 = 4

【结果判定】
4 < 6 → 大失败！需要应用debuff并升级叙事。

【LLM第四步：升级叙事 + 应用debuff】
应用：SO-002 被标记 (Marked) + EN-002 引起注意 (Noticed)

"你听到对讲机的声音:'监控3号，东走廊有异常移动。'
'收到，正在回放。'
'...这是一个人影。不在访客名单上。启动追踪协议。'

那一刻，你知道自己暴露了。
下一次被这个设施的任何安保看到，他们会立即识别。
而且现在他们正在追踪你的位置——你能听到走廊里传来的急促脚步。"

【剧情继续钩子】
- 需要立即逃脱（EN-001 被困状态已形成）
- 或者找到新的伪装/证件（MA-001 缺乏资源）
- 或者需要砾/其他同伴的帮助来脱身
```

### 案例2：欺骗被识破 — 运气拯救

```
【原始情景】
玩家说："我告诉守卫我是新派来的维修工人。"
DC: 15（这个守卫很警惕）
roll: 8（含魅力修正）
结果：失败

【LLM第一步：初始失败叙事】
"你编好了故事，走向值班室。
'你好，我是来检查电气系统的。'
守卫抬起头，眼睛眯起来。
'维修工人？我没有收到通知。'
他伸手去检查名单...
你知道你的名字不在那上面。"

【判断是否需要失败后roll】
- 这是社交欺骗，但失败幅度不大（8 vs 15 = -7）✓ 触发条件1
- 涉及权威人物，有中等风险 ✓ 触发条件2
→ 进行失败后roll点

【计算失败后roll】
属性修正：魅力 +2
情境修正：中等风险（被发现但不是生死） 0
负面惩罚值：常规失败 -2
骰子结果：d20 = 20 ✓

失败后roll = 20 + 2 + 0 - 2 = 20 → 大成功！！

【结果判定】
20 = 20 → 大成功！避免debuff，获得隐藏机会。

【升级叙事：运气拯救】
"守卫正要按警报——
突然间，一个人形的警告响了。
'所有队伍，立即集中到5楼。有真实的入侵迹象，
中央服务器区域。重复——'

守卫的脸色变了。他看看你，又看看警告设备。
'该死。'他跳起来，'等等，你...'其他警卫跑了过来。
'赶快！'有人吼。

在混乱中，那个守卫被同事拉走了。'稍后再检查维修名单。'
你意识到——那个真实的入侵警告，完全救了你。
有人在同一时间进行了另一场行动，为你创造了掩护。"

【隐藏机会】
- 下一个在此区域的隐蔽判定 +2（因为系统忙碌）
- 或者：发现有另一个罗德岛特工也在这边执行任务
```

### 案例3：武力对抗 — 全面失败

```
【原始情景】
玩家说："我和这两个守卫对打。"
DC: 13（两个训练有素的守卫）
roll: 4（含力量修正）
结果：大失败 (roll本身 = 1)

【LLM第一步：初始失败叙事】
"你冲上去，试图制服第一个守卫。
他反应很快，用警棒挡开你的攻击。
第二个守卫从侧面靠近——
你被夹在中间。你的动作太急促，太缺乏计划。"

【判断是否需要失败后roll】
大失败 (roll = 1) → 自动触发，且有额外惩罚

【计算失败后roll】
属性修正：力量 +0
情境修正：面对武装敌人且已进入对抗 -5
负面惩罚值：大失败 -5
骰子结果：d20 = 3

失败后roll = 3 + 0 - 5 - 5 = -7

【结果判定】
-7 < 6 → 大失败！需要多个debuff。

【升级叙事：灾难后果】
应用：PH-002 重伤 + ME-002 恐惧 + SO-002 被标记

"第二个守卫的警棒直接击中了你的肋骨。
剧痛——不，那不仅是疼痛，那是骨头在哭喊。
你跪在地上，呼吸变得困难。

第一个守卫抬起警棒，准备再来一击。
但砾从阴影里扑出来，她的手术刀闪闪发光。
'住手！'她的声音很尖锐。
那瞬间的混乱救了你——砾拉着你逃离。

后来，当你终于能深呼吸时，你知道肋骨裂了。
还有——你听到那个守卫的对讲机里传来的声音：
'...那就是那个人。罗德岛的。把照片发给全队...'"

【后续影响】
- 需要医疗处理肋骨伤（否则会恶化）
- 对武装冲突产生心理阴影，下次对抗判定 -2
- 该地点的所有守卫现在都认识你的脸
- 砾对你产生了新的担忧（可能触发对话或支线）
```

## 常见情况处理

### Q: 玩家连续失败多次，debuff叠加会不会太过分?

**A:** 是的，可能会。处理建议：

1. **允许一定的叠加** - 体现"事情真的在恶化"的感觉，但...
2. **提供清除机会** - 在叙事中主动插入可以清除debuff的机会
   - "你发现了一个医疗室，可以处理那个伤口"
   - "砾说：'我认识一个人，也许能帮忙隐藏你的身份'"
3. **改变挑战形式** - 而不是增加惩罚
   - 玩家移动变慢 → 改为需要"躲避更多的监视"
   - 玩家受伤 → 改为"需要支援"而非单打独斗

### Q: 玩家roll到大成功(20)，但原始行为也失败了。这是否不公平?

**A:** 不。大成功代表"幸运的转机"，这在很多TTRPG系统中都有体现。示例：
- 原本上当了，但同时发生了另一个事件转移了对方的注意
- 原本暴露了，但发现了敌人的弱点
- 原本被追捕，但逃进了一个意想不到的盟友的地盘

### Q: 我应该如何追踪玩家当前有哪些debuff?

**A:** 建议方案：

1. **在场景描述中持续提及** - 每个主要行动时
   - "你的肋骨还在疼，每一步都提醒你。"
   - "你能感觉到，安保在问彼此：'这是那个人吗?'"

2. **创建简单的"状态表"** - 在会话开始时
   ```
   【当前Debuff】
   - 重伤(PH-002): 3回合剩余
   - 被标记(SO-002): 7回合剩余
   - 缺乏资源(MA-001): 直到获得新工具
   ```

3. **定期清除检查** - 在关键时刻
   - 场景转换时
   - 玩家长休息后
   - 完成了与debuff相关的行为后

### Q: 有没有什么debuff是"不能清除"的?

**A:** 没有绝对的"不能清除"，但有些需要特殊条件：

- **长期debuff** (如被标记、欠债) - 需要实质性的行动
  - 不是简单地"等待"，而是需要做出改变
  - 如"被标记"需要伪装/改变身份/时间流逝后新安保员上岗

- **需要外力的debuff** (如被困、被利用) - 可能需要同伴帮助
  - 这正是创造角色互动和支线任务的机会

## 快速检查清单

使用这个清单确保你正确应用机制：

**何时应用失败后roll**
- [ ] 玩家行为失败，且...
- [ ] 失败幅度 ≥ 5? OR 属于高风险行为? OR roll = 1?
- [ ] 这是动态偏离且不是已预设的失败结果?

**Roll计算**
- [ ] 选择了正确的属性修正(关联性)?
- [ ] 评估了情境修正(-5 ~ +2)?
- [ ] 应用了正确的负面惩罚值(-2 ~ -5)?
- [ ] 进行了d20骰?

**结果处理**
- [ ] 根据结果为叙事添加了debuff或运气转机?
- [ ] 在叙事中**具体化**了后果(不是直说"你获得了debuff")?
- [ ] 为玩家提供了清除debuff的**潜在路线**?
- [ ] 如果有debuff，是否在后续场景中持续提及?
