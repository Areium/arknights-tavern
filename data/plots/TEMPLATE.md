# ==============================================================================
# 剧情文件模板 (Plot Template)
# ==============================================================================
# 本文件用于定义游戏中的剧情节点。
# 每个剧情一个 .md 文件，系统根据触发条件和前置状态自动激活。
#
# ── Frontmatter 字段说明 ──
#
# id:              剧情唯一标识（必填），用于系统引用，建议使用英文下划线命名
#                   示例：chernobog_rescue, reunion_first_encounter
# name:            剧情中文名（必填），用于日志和 AI 引用
# category:        剧情类型（必填）：
#                  - "main"      → 主线剧情，通常有前置条件
#                  - "side"      → 支线剧情，可独立触发
#                  - "character" → 角色个人剧情，特定角色在队时触发
#                  - "random"    → 随机事件，满足条件时概率触发
#                  - "world"     → 世界观背景事件，用于丰富世界观
# priority:        优先级（1-10），同时满足多个剧情时，高优先级优先触发
#
# trigger:         触发条件（必填），至少满足一项即可触发
#   location:       地点列表（可选），当前所在地点匹配时触发
#                   示例：["控制中枢", "训练室"]
#   character:      角色列表（可选），当前对话角色匹配时触发
#                   示例：["阿米娅"]
#   keywords:       关键词列表（可选），用户输入包含关键词时触发
#                   示例：["切尔诺伯格", "救援", "博士的记忆"]
#   time:           时间段（可选），如 "morning" / "afternoon" / "evening" / "night"
#   weather:        天气列表（可选），当前天气匹配时触发
#                   示例：["雷暴", "暴风雪"]
#   probability:    概率触发（0-100），仅 category=random 时有效
#
# prerequisites:   前置条件（可选），所有条件必须同时满足
#   plot_completed: 必须先完成的剧情 ID 列表
#                   示例：["chernobog_arrival"]
#   character_met:  必须先遇到的角色列表
#                   示例：["阿米娅"]
#   faction_known:  玩家必须已知的势力列表
#   item_owned:     玩家必须携带的物品列表
#                   示例：["博士的战术终端"]
#
# effects:         剧情完成后生效的效果（可选）
#   unlock_plots:   解锁的新剧情 ID 列表
#   unlock_locations: 解锁的新地点列表
#   faction_change: 势力关系变化，格式为 {"势力名": "新关系"}
#   add_item:       获得的物品列表
#   character_available: 变为可对话的新角色列表
#
# repeatable:      是否可重复触发（默认 false）
# cooldown:        冷却时间（游戏内回合数，仅在 repeatable=true 时有效）
# ==============================================================================

# 剧情名称（示例：博士的第一次任务简报）

## 剧情概述

用 1-2 句话描述该剧情的核心内容。这是 GM 在触发剧情时的参考。

示例：
阿米娅和凯尔希在控制中枢向博士汇报罗德岛当前的任务状况，并介绍近期的行动目标。

## 触发场景

描述剧情触发时的环境和参与角色。AI 会使用这些信息来设置场景。

示例：
**地点**：罗德岛控制中枢
**时间**：早晨
**参与者**：阿米娅、凯尔希、博士
**触发方式**：首次进入控制中枢时自动触发（主线剧情 #001）

## 剧情脚本

**（核心章节）** 描述剧情的推进流程。每个节点包含：
- 场景描述
- 角色对话/行动
- 玩家可选择的回应方向（不一定要穷举，给出方向性指引即可）
- 分支条件

格式示例：

### 节点 1：开场

**场景**：控制中枢的主屏幕显示着泰拉大陆的全息地图，阿米娅站在屏幕前，凯尔希在一旁翻阅数据板。博士推门进入。

**阿米娅的对话方向**：
- 向博士问好，表达对博士恢复的关心
- 简要介绍罗德岛当前面临的几个任务选择
- 询问博士的意见

**玩家可选择的方向**：
- 关心阿米娅的状态
- 直接询问任务详情
- 对凯尔希提问

### 节点 2：任务选择

**场景**：阿米娅调出三份任务简报，分别是：资源采集任务、感染者救援任务、和龙门的外交任务。

**分支逻辑**：
- 如果玩家选择了资源采集 → 解锁地点"制造站"，获得物品"采集清单"
- 如果玩家选择了感染者救援 → 解锁地点"医疗部"，角色"凯尔希"好感度+1
- 如果玩家选择了外交任务 → 解锁地点"龙门联络处"，解锁势力"龙门"

### 节点 3：收尾

**场景**：任务确认后，各人离开控制中枢准备出发。

**凯尔希的对话方向**：
- 简短的任务提醒（根据选择的任务给出具体建议）
- 对博士状态的隐晦关心
- 先行离开处理其他事务

## 关键对话参考

提供一些关键的对话句子或对话方向，帮助 AI 把握角色的说话方式。

示例：
- 阿米娅："博士，有您在真是太好了。无论前方的路有多难，只要和您一起，我就有了继续前进的勇气。"
- 凯尔希："不要感情用事。博士，你的决策直接影响所有干员的性命。"
- 阿米娅（转向凯尔希）："凯尔希医生，博士才刚刚恢复，请不要太严厉了。"

## 后续影响

描述剧情完成后对游戏世界的持久影响：
- 解锁的新内容（地点、角色、剧情）
- 改变的势力关系
- 获得的物品或信息
- 角色好感度变化

# 写作指南

## 核心原则

1. **脚本是指南而非剧本**：AI 会根据角色卡自由发挥，剧情脚本提供的是方向指引和关键转折点，而非逐字固定台词
2. **分支要扁平**：不要设计超过 3 层深的分支树，每层 2-3 个选项即可，避免 AI 迷失在复杂的条件逻辑中
3. **前置条件克制**：不要给支线剧情设置过多前置条件——一个好剧情应该尽量让玩家容易遇到
4. **关键对话提供锚点**：在"关键对话参考"中给出 2-3 句标志性台词，AI 会据此校准角色的语气
5. **后续影响要有意义**：不要只是 "好感度+1"，要给出具体可感知的变化（新地点、新对话选项、新信息）

## 常见错误

- ❌ 把剧情脚本写成小说 —— AI 无法解析大段无格式的叙事文字
- ✅ 使用结构化的节点、清晰的对话方向、明确的分支条件
- ❌ 过多的分支和条件嵌套 —— 实际运行中 AI 很难精确命中复杂条件
- ✅ 简单的 2-3 分支，每个分支对应明确的结果
- ❌ 忽略了剧情与角色卡的一致性 —— 剧情中角色的行为应与角色卡中的性格设定保持一致
- ✅ 在写剧情前确认相关角色的角色卡，确保行为动机不冲突
