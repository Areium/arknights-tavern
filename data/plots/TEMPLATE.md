# 剧情名称

## 剧情概述

用 1-2 句话描述该剧情的核心情境——不是预设的故事走向，而是这个世界此刻存在的矛盾切片。

示例：
阿米娅和凯尔希在控制中枢向博士汇报罗德岛当前的任务状况。三个紧急任务同时出现，罗德岛人手有限——而博士的每一个选择都在塑造指挥官在干员心中的形象。

# 系统设计说明（非模板内容，供开发者参考）

## 已生效的功能

### 节拍追踪
章节和节拍由系统自动解析（`## 章节 N：Title` + `#### beat_id`），推进状态记录在会话的 `plot_state.md` 中。每个节拍约 8 轮叙述后自动推进到下一个。

### 开场注入
`## 开场设置` body 节在首次叙述时注入 LLM 上下文，之后自动清除。`initial_*` frontmatter 字段设置场景环境（地点/时间/氛围/角色）。

### 任务管理
`## 任务` 节中的任务定义被解析为任务状态，由 LLM 在叙述中逐步激活和更新。

### 关键对话参考
`## 关键对话参考` body 节被提取并注入 `plot_state.md`，作为 LLM 角色语气校准参考。

## 规划中的功能

### 偏离系统（deviation_policy）
玩家可以通过偏离点跳出默认章节路径。偏离判定：条件检查 → d20 roll vs difficulty。偏离成功可触发 replan（LLM 重规划后续章节）。

### 定时炸弹（tension_clock）
玩家不作为时世界自动推进。每个阶段在 NPC 对话中体现，给玩家持续的紧迫感。

## 六大核心原则

### 1. 写情境，不写故事
准备一个存在尖锐矛盾的世界切片，不预设玩家会怎么做。剧情文件是**情境生成器**而非**剧本**。

### 2. 动机驱动，而非事件驱动
每个 NPC 有独立的"想要/害怕/愿意为此"三要素。事件是 NPC 行动的结果，不是等待玩家触发的机关。

### 3. 节点化弹性结构
章节之间的 next 链是默认路径。每个章节内有多个入口和出口，玩家可以通过偏离点跳出默认路径。

### 4. 三线索规则
任何关键信息至少提供 3 条独立的获取路径（人证、物证、现场痕迹）。一条线索断了，还有别的路。

### 5. 失败即新剧情
判定失败、推理错误不应导致故事卡死。偏离失败应产生新的剧情分支而非阻塞推进。

### 6. 定时炸弹
如果玩家什么都不做，世界会自己往前走。每一阶段都应在 NPC 对话中有所体现。

## 战斗场景中的敌人引用

当剧情包含战斗场景时，应在章节节拍中列出战斗中出现的所有敌人类型。敌人数量的建议：
- tier 1（杂兵）：4-8 个
- tier 2-3（标准/精锐）：2-4 个
- tier 4（精英）：1-2 个
- tier 5-6（首领/传说）：1 个（通常作为章节 Boss）

LLM 在解析战斗场景时会根据敌人索引自动加载对应敌人文件。敌人属性与角色属性使用同一套 8 属性系统。
